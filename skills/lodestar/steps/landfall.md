# 4. Landfall — close the voyage

### 4a. Check
Send the landfall check (SKILL.md, The crew) with: the heading and "done when" lines, the scope table, the project
rules' full-suite command, the full diff range, and the docs page if one was written. Show its report as is.
A failure becomes a waypoint: set `Stage: Sail` and fix it there.

### 4b. Sighted islands
Hand over the list for the user to decide, item by item: new ticket · drop.

### 4c. Summary
Write `summary.md` from templates/summary.md — how the voyage went, not how the system works (that is the docs'
job): heading, islands and the user's summaries, decisions with the options set aside and why, course changes, the going-back table,
concepts learnt. Then ask the user for their own lines. Gate: no landing without them.

### 4d. Compact
Append passage-plan.md and log.md to archive.md, under a heading with today's date, then delete them.
The folder keeps summary.md, archive.md and research/ — the lexicon's `where` pointers still resolve.

### 4e. Git
Offer what the project rules' Git section says (pull request · local merge · keep the branch). Nothing is pushed,
merged or deleted without the user's word for that exact action.

Set `Stage: Landed` on the first line of summary.md. The voyage now shows last in the sea.
